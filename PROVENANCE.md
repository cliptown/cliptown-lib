# Dependency provenance

The initial release is tied to the following reviewed inputs:

| Dependency | Immutable source |
|---|---|
| `cliptown/cliptown-interfaces` | `ec4f820bcc9181c2423a6963d3890ddc8ef18b97` |
| Rust toolchain minimum | `1.88.0` |
| Zed CLI validation source | `zed-pkg/zed-cli@751358fe130e64b646844bc7d857c4cff215ca2d` |

The interface commit is the merge of `cliptown/cliptown-interfaces#14`; it adds
only the root Cargo workspace needed to consume the existing generated Rust
package. The interface, MemeBank contract, and certified Zed artifact matrices
passed unchanged before merge.

`Cargo.lock` is generated by Cargo. The current version-only `.zpkg.lock` is the
resolver-owned bootstrap lock retained by the later DEN-3287 integration. It
must be replaced only by the canonical Zed resolver when
`cliptown/cliptown-interfaces` has a resolvable `v0.1.0` package/tag; it must not
be hand-authored or deleted merely to make CI appear green.

Cargo crates.io packaging is intentionally not a release gate while the
canonical interface crate is consumed from an immutable Git revision and is
not present in the crates.io index. Rust builds, tests, documentation, and the
credential-free Zed package are the supported release evidence for v0.1.0.

Release artifacts must bind the repository, source commit, package version,
workflow run, and checksums without embedding credentials.
